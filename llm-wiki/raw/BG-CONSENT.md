# Cookies и аналитика BotGate

Редакция документов: 30.10.2026. Версия выбора: `2026-10-30-goals`.

## Поведение

- Панель: «Используем cookies для работы сайта и анализа посещаемости. Метрику и рекламную атрибуцию можно отключить в настройках cookies». Действия: «Согласен», «Настройки», «Подробнее». Крестика нет; Escape не закрывает первое уведомление.
- «Согласен» сохраняет явное согласие и скрывает панель. Открытие страницы, отсутствие выбора и запуск счётчика не создают запись о согласии.
- «Настройки» открывает и повторным нажатием сворачивает блок состояния и отключения аналитики. Ссылка «Cookies» внизу страницы всегда открывает плашку со скрытыми настройками. Повторная проверка состояния при возврате на вкладку не закрывает открытые настройки. «Закрыть» в настройках закрывает всю плашку без изменения выбора и записи согласия; до перезагрузки страницы проверка состояния сама её не открывает.
- Панель и обычная Метрика подключены на главной, в публичной документации и руководствах (`guides.*`). После трёх успешных действий счётчик дополнительно кратковременно запускается на странице результата для отправки цели (см. ниже). На остальных страницах кабинета, ботов, авторизации и в Filament счётчика нет. Реальный счётчик работает только в production.
- После успешной проверки сохранённого выбора Метрика запускается по умолчанию, если нет отказа. При ошибке проверки, после отказа и без JavaScript запросов к Метрике нет. Безусловного noscript-пикселя нет.
- Вебвизор, карта кликов и отслеживание ссылок отключены. Счётчик использует стандартный URL и referrer: принудительное удаление query string и подмена referrer убраны, чтобы не мешать рекламной атрибуции. На публичных URL, в заголовках и referrer нельзя размещать секреты и персональные данные. Настройки и фильтры кабинета Метрики проверяются отдельно.

## Хранение и отключение

- `GET /cookie-consent` проверяет зашифрованную Laravel cookie; `POST /cookie-consent` принимает явный выбор `accepted`/`declined` и актуальную версию. Оба ответа имеют `Cache-Control: no-store, private`. GET не записывает согласие.
- POST защищён web middleware / CSRF и ограничен 30 запросами в минуту. Публичный API BotGate не меняется.
- Cookie `botgate_cookie_consent_v2`: 180 дней, HttpOnly, SameSite=Lax, Secure в production или при HTTPS, path `/`, без Domain (только текущий host). Создаётся через Symfony Cookie, чтобы не наследовать SESSION_DOMAIN; конфигурация — `config/cookie-consent.php`.
- Новое имя исключает конфликт с прежними одноимёнными cookies `botgate_cookie_consent` на основном домене и dev. Пока нет нового действующего выбора, сервер читает старую cookie. При дублях проверяет все значения исходного Cookie-заголовка через шифрование Laravel и привязанный к имени префикс; среди читаемых действующих старых решений отказ имеет приоритет. Новое действующее решение имеет приоритет над старыми. Cookies родительского домена не удаляются, поскольку могут использоваться основным сайтом. Значения cookies не пишутся в журнал.
- Действующий отказ предыдущей версии сохраняет силу. Старое согласие не считается согласием на новую редакцию: панель появляется снова, при отсутствии отказа действует включённая по умолчанию аналитика.
- Отказ дополнительно сохраняется в localStorage (`botgate_analytics_blocked`) до нового успешно сохранённого согласия или удаления данных сайта пользователем. Он продолжает действовать при истечении cookie, изменении версии и сбое записи отказа. Если localStorage недоступен, сохраняется отказ в cookie и памяти открытой страницы; после удаления/истечения доступного хранилища сайт не может распознать прежний отказ.
- После нажатия «Согласен» браузер повторно проверяет сохранённую cookie. Только успешная проверка снимает локальный запрет. Ошибка сохранения выбора отключает аналитику и показывает сообщение.
- При отказе счётчик немедленно останавливается через `destruct`, доступные first-party cookies и ключи `_ym*` очищаются. Сессионные cookies не затрагиваются. Уже отправленные данные и cookies доменов Яндекса этой кнопкой не удаляются.
- BroadcastChannel и события localStorage синхронизируют выбор между вкладками. При возврате на вкладку состояние проверяется снова. Загрузка скрипта, завершившаяся после отказа, не запускает счётчик.
- Журнал `storage/logs/cookie-consent-YYYY-MM-DD.log` содержит случайный ID решения, ID предыдущего действующего решения, версию, время, срок и явный выбор. Не содержит IP, user agent, email, токенов или истории посещений. Retention 365 дней, daily, permissions 0640. Очистка выполняется при ротации/записи; длительно неиспользуемые архивы удаляются по принятому сроку хранения.
- Миграция БД не требуется. Нужен доступ приложения на запись в обычный `storage/logs`.

## Внутренний счётчик просмотров руководств

- JavaScript отправляет `POST /guides/{slug}/view` на том же домене при первом показе опубликованной статьи в видимой вкладке. Маршрут защищён Laravel CSRF и ограничен 60 запросами в минуту. Открытие каталога, обычный GET и загрузка статьи без JavaScript просмотр не записывают.
- Счётчик работает независимо от Яндекс.Метрики и выбора в панели. Для дедупликации используется существующая Laravel-сессия. HMAC от ID статьи и ID сессии образует ключ временной отметки в Redis. Отметка создаётся атомарно, живёт 86 400 секунд и при повторе не продлевается. При ошибке записи итога приложение освобождает свою отметку для следующей попытки. Новые cookies не создаются.
- В `guide_daily_views` сохраняются ID статьи, календарная дата и количество. Даты считаются в часовом поясе приложения. В Filament период включает сегодня и предыдущие 29 дней, а общий итог начинается с запуска счётчика. Один человек может дать несколько просмотров в разных сессиях.
- Все процессы одного окружения должны использовать один Redis для блокировок кеша и одинаковые префиксы. Счётчик обращается к хранилищу `cache.stores.redis` и его `REDIS_CACHE_LOCK_CONNECTION` (по умолчанию `default`). Перед выкладкой проверьте доступность этого подключения из процессов приложения. Удаление или вытеснение ключей Redis до истечения TTL может привести к повторному подсчёту.
- При выкладке применить миграцию `2026_11_03_000001_create_guide_daily_views_table` и опубликовать новую сборку фронтенда. Локальная проверка на SQLite в памяти — `php85 artisan test --compact --filter=GuideViewsTest`.

## Документы

Публичные документы требуют отдельной редакции. В действующем согласии на веб-аналитику указано прежнее название кнопки и обещана возможность пользоваться сайтом без аналитики. В политике и согласии нужно отдельно описать внутренний подсчёт просмотров и область действия переключателя. Опубликованные документы в этой задаче не пересобирались.

Генератор `bot-gate-main/scripts/build_legal_documents.py` создаёт четыре DOCX в `resources/legal-documents`. `scripts/render_legal_pdfs.py` создаёт публикуемые PDF в `public/documents`. Ссылки и имена документов сохранены; «Подробнее» открывает `BotGate_Analytics_Consent.pdf`.

Политика, общее согласие, пользовательское соглашение и отдельное согласие описывают включённую по умолчанию аналитику и последующее отключение. Политика и отдельное согласие также описывают привязку источника к аккаунту. Отдельное согласие относится к обработке с момента нажатия «Согласен» и не подтверждает согласие на предшествующий сбор. Регистрационное согласие не включает аналитику. Прежние редакции DOCX/PDF находятся в `resources/legal-documents/archive/2026-09-26` и `2026-10-02`; генераторы их не перезаписывают.

Описание фактического поведения не устанавливает само по себе правовое основание обработки до согласия. Применимость такого основания требует отдельной юридической оценки; нажатие кнопки не действует задним числом. Регистрационная отметка о принятии условий не включает веб-аналитику; скрытое поле формы передаёт только результат проверки настройки в браузере и не считается согласием.

## Источник регистрации

- На главной, в документации, руководствах и на GET `/register` браузер после успешной проверки настройки сохраняет первый вход и последний вход с метками. Возврат без меток не заменяет последний рекламный переход. Снимки переходов целиком независимы: отсутствующие параметры не наследуются от предыдущего клика. Отсутствие меток не доказывает прямой заход.
- Белый список: `yclid`, `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `group_id`, `phrase_id`, `source_type`, `placement`, `device_type`, `region_id`. Значения хранятся строками. Дополнительно сохраняются серверное время перехода, путь входной страницы без query/fragment и только домен referrer. Полный URL и произвольные параметры не сохраняются. Ограничения длины в байтах заданы в `config/acquisition.php`; длинные значения обрезаются по границе UTF-8. Снимок размером более 1400 байт отклоняется с HTTP 422; регистрация при этом остаётся доступной без рекламной привязки.
- Когда публичный счётчик доступен, его `getClientID()` вызывается после инициализации и с короткими повторными попытками. ClientID сохраняется отдельно, как строка; его отсутствие не мешает регистрации. На страницах результатов действий отправляются три цели, описанные ниже. `setUserID` и передача офлайн-конверсий не добавлены.
- Host-only cookies `botgate_acquisition_first_v1`, `botgate_acquisition_last_v1`, `botgate_acquisition_client_v1`: шифрование Laravel, HttpOnly, SameSite=Lax, Secure при HTTPS/production, path `/`, до 30 дней. Истечение каждого снимка дополнительно проверяется по серверному времени его записи: повторная отправка старой cookie не продлевает окно. После успешной регистрации cookies удаляются. Dev и production не разделяют эти cookies.
- `POST /acquisition` записывает только cookies гостя. `DELETE /acquisition` очищает cookies; `withdrawal=true` также удаляет привязку текущего авторизованного пользователя. Маршруты защищены CSRF, ограничены 60 запросами в минуту, ответы `no-store, private`. По переданному извне user ID записи не изменяются. Публичный API BotGate и Go Proxy не меняются.
- При регистрации пользователь и `user_acquisitions` создаются в одной транзакции. Таблица содержит уникальный `user_id`, `first_touch`, `last_tagged_touch`, `metrika_client_id`, timestamps. Отсутствие JS, ошибка проверки настройки, локальный отказ или действующий отказ в cookie исключают привязку; аккаунт создаётся обычным образом. Существующие аккаунты при дальнейших посещениях не получают новую атрибуцию. В административном разделе [«Реклама»](advertising.md) сохранённый источник сопоставляется с регистрацией, подтверждением почты, добавлением бота и рабочей активностью; сведения не передаются во внешние системы.
- Явный отказ и обнаружение ранее сохранённого отказа прекращают сбор, очищают три cookies и удаляют привязку текущего авторизованного аккаунта. При локальном отказе очистка вызывается отдельно от записи согласия, поэтому сбой журнала не разрешает привязку при регистрации. Временный сбой проверки настройки очищает только cookies, но не историю аккаунта. Рабочие данные ботов и `bot_daily_stats` не затрагиваются.
- Сервер проверяет действующий отказ также на web-запросах без JS. Браузер учитывает localStorage и синхронизацию вкладок. Запись cookies и их удаление упорядочены внутри вкладки, чтобы ответ старого запроса не восстановил данные после отказа. Если сервер недоступен, физическое удаление HttpOnly cookies и строки БД возможно после восстановления связи; локальный запрет уже действует.
- После выхода из аккаунта сайт не определяет, чью сохранённую привязку удалить. Для её удаления требуется войти в соответствующий аккаунт с сохранённым отказом либо обратиться в поддержку. В БД привязка хранится до удаления аккаунта или более раннего отказа авторизованного пользователя; удаление пользователя каскадно удаляет атрибуцию. Кросс-браузерная и кросс-устройственная привязка гостя не выполняется.

Пересборка из `bot-gate-main` (Python с `python-docx` и `reportlab`, Windows Times New Roman):

```text
python scripts/build_legal_documents.py
python scripts/render_legal_pdfs.py
```

Публикуемые PDF проверяются визуально после пересборки. DOCX служат исходниками; их отдельный Word-совместимый рендер требует LibreOffice, отсутствующего в текущей среде.
